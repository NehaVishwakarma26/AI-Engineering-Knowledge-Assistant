Retrieval-Augmented Generation (RAG) is an architecture that combines information retrieval with language-model generation. Instead of asking a language model to answer a question entirely from parameters learned during training, a RAG application first searches an external knowledge collection and then supplies relevant evidence to the model.

A typical RAG system has an ingestion or indexing stage and a query stage. During ingestion, source documents are loaded, cleaned, divided into chunks, enriched with metadata, converted into embeddings, and stored in a retrieval system. During a query, the user's question is transformed into a representation suitable for retrieval. The system retrieves candidate passages, constructs a context window, and sends the evidence together with the question to a language model.

Chunking is important because documents are normally too large to retrieve or pass to a model as a single unit. Fixed-size chunking is simple, while recursive or semantic chunking attempts to preserve meaningful boundaries. Chunk overlap can reduce the chance that information split across boundaries becomes impossible to retrieve.

A basic RAG pipeline usually performs dense vector retrieval. The query is embedded and compared with stored document embeddings. The highest-scoring chunks are selected and placed into the generation prompt. Metadata such as source name, page number, section, or document identifier can be retained so that the final response can provide citations.

RAG does not automatically guarantee factual answers. Retrieval quality, chunk quality, prompt construction, model behavior, and evaluation all affect the result. A system can hallucinate even when retrieval succeeds if the model ignores evidence or if the retrieved evidence is insufficient.

Advanced RAG systems can use contextual retrieval, hybrid search, query rewriting, reranking, multi-stage retrieval, caching, and retrieval evaluation. Contextual retrieval adds document-level information to individual chunks before embedding them. Hybrid retrieval combines lexical retrieval such as BM25 with dense semantic retrieval. Reranking applies a second relevance model to a candidate set before generation.

Evaluation should distinguish retrieval quality from generation quality. Retrieval metrics include recall@k, precision@k, mean reciprocal rank, and normalized discounted cumulative gain. Generation can be evaluated for groundedness, answer relevance, and correctness.
